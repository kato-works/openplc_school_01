# OpenPLCを勉強してみよう #01

## OpenPLCとは？

OpenPLCとは、2013年から2014年にかけてブラジルの電気エンジニアのThiago Alvesさんによって開発がスタートされた、世界初の「完全オープンソースのプログラマブルロジックコントローラ（PLC）」です。商用PLCが高価だったため、安価なマイコンボードを使って自動車のクラッシュテストを自動化したのが始まりです。

後に国際標準規格「IEC 61131-3」に準拠するようになりラダーロジック（LD）やストラクチャードテキスト（ST）といった、5つの標準言語すべてに対応します。これにより、シーメンスのPLCを完全に代替する機能を持つに至りました。

オープンソースであることから学会から注目され高く評価されます。これにより、サイバーセキュリティ研究の標準プラットフォームとして発達し、世界の研究者がペネトレーションテスト（侵入実験）やハッキング対策のシミュレーションを行うための必須ツールとなりました。

現在はAutonomy Edgeとして起業され、プラットフォームも多岐に渡りコミュニティーも10,000人を越える規模に成長しています。

## いやそもそもPLCって。

PLCとは、プログラマブルロジックコントローラの略で、工場の機械や装置を自動で動かすための小さなコンピュータです。日本では「シーケンサ」とも呼ばれます。主な役割として、順序制御、条件制御、時限制御を行います。

PLCが発明される前は、機械を順序どおりに動かすシーケンス制御を行うためには、リレー装置やタイマ装置などを用いて電気回路を設計していました。

ゼネラルモーターズはモデルチェンジのたびにラインの電気回路の組み直しが必要であることを問題視して、リレーによる回路を電子的に代替する方法を模索して、ロックウェル社がPLCを開発しました。

もともと電気回路をプログラムで代替する装置ですので、プログラミングは「言語」ではなく、ラダーと呼ばれる「回路図」で行われます。そのためPLCの取扱は情報処理技術者の分野というよりは、どちらかというと電気工事士などの電気技術者の領域となります。

## じゃあOpenPLCとか言わずに買ってくればいいんじゃないの

世界シェアは以下のとおりです。

- シーメンス（ドイツ）：30~35%
- ロックウェル（USA）：15～20％
- 三菱電機（日本）：10～15％
- シュナイダー（フランス）：5～10％
- オムロン（日本）：5～10％

なお、日本国内では

- 三菱電機：45〜50%
- オムロン：20〜25%
- キーエンス：10〜12%
- 富士電機：3〜5%

三菱電機・オムロンの独壇場でしたが、2020年コロナ禍の部品供給難の際に、キーエンスが直販・低価格化・高付加価値化により中小規模案件で一気にシェアを伸ばしているため、今後は業界地図が塗り替わりそうです。

では、なぜThiago AlvesさんがOpenPLCを開発したかというと、「高い」からです。

ひとつはハードウェア、もうひとつは開発環境です。開発環境も体験版が準備されていることが多いですが、100,000円から450,000円と個人で扱うには高額です。またハードウェアについては新品を手に入れようとすると、キーエンスを除くと商社を介して購入する必要があり、学習ハードルはさらに上がります。

なお、もう一つの選択肢としてソフトウェアPLCというジャンルも存在しています。こちらは、PCにインタフェースボードを追加することでPLCとして動作させるというものになります。欧州を中心に普及が進んでおり、ドイツのCODESYSが実質のデファクトスタンダードになってきています。CODESYSは2023年以降、開発環境のライセンスを無償化しており、代わりに動作するデバイス単位でのライセンスを採用しています。€30~€600と巾広となっており、IO数とアプリケーションサイズで課金されます。


## 組み込みソフト開発とPLCラダー開発の境界面

ソフトウェアによって、PLC部分の開発を担うことは可能です。
動作仕様として現場で読めるべきものはラダー、装置の内部機能として隠蔽したいものはC、と考えると切り分けやすいです。

| 判断軸 | PLCラダー向き | 組み込み向き |
| --- | --- | --- |
| 主な内容 | 機械の動作・順序・インターロック | 通信、演算、デバイス制御 |
| 変更する人 | 	制御設計者、保守担当者 | 	組み込みソフト開発者 |
| 変更頻度 | 機種・顧客仕様ごとに変わる | 基板・CPU・通信仕様ごとに変わる |
| 時間特性 | PLCスキャン周期で十分 | 高速・非同期・割込み処理が必要 |
| デバッグ | 接点のON/OFFを追いたい | ログ、デバッガ、単体テストで追う |
| 表現適性 | 論理、タイマー、カウンタ、状態遷移 | 	複雑な数式、配列、バッファ、プロトコル |
| 再利用単位 | 	機械機能単位 | ドライバ・ライブラリ単位 |

### PLCラダーに置くもの

例えば、次のような「機械がどう動くべきか」はラダーが向いています。

- 起動・停止シーケンス
- 自動／手動モード切替
- 電磁弁やリレー出力の条件
- センサー入力による動作判断
- 各種インターロック
- タイムアウト、再試行回数
- 異常検出と異常コードの決定
- オペレータ操作に対する応答
- メンテナンス時の強制操作条件

### 組み込みソフトウェアに置くもの

組み込みソフトウェア側には、ラダーから見て「機能ブロック」や「仮想デバイス」に見える処理を置きます。

- GPIO、ADC、PWMなどの低レベルドライバ
- CAN、J1939、Modbus、USB、UARTなどの通信処理
- CANメッセージの送受信キュー
- J1939のアドレスクレームやTransport Protocol
- ウォッチドッグ
- フラッシュメモリへの設定保存
- ブートローダー、ファームウェア更新
- 高速サンプリング
- フィルター処理
- 浮動小数点を多用する演算
- CRC、暗号、圧縮
- 診断ログ収集
- PLCランタイムそのもの

たとえばJ1939の場合、PGNの送受信やパケット分割までラダーで実装すると、動作確認も再利用も難しくなります。C側で処理して、ラダーには次のような変数だけを公開する形が扱いやすいです。

## 何を勉強するの？

国際標準規格「IEC 61131-3」では以下の５つがPLCのプログラミング用の言語として定義されています。

- ラダー・ダイアグラム（LD言語）
- ファンクション・ブロック・ダイアグラム（FBD言語） 
- ストラクチャード・テキスト（ST言語） 
- インストラクション・リスト（IL言語）
- シーケンシャル・ファンクション・チャート（SFC言語）

海外ではC言語に近く記述しやすいストラクチャード・テキストがよく使われていますが、日本ではラダー・ダイアグラムがほとんどを占めます。

本セッションではこのラダー・ダイアグラムをOpenPLC上で記述して、マイコンボードで動かすまでを対象としています。
